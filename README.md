# IHCA 團隊復甦模擬器 v4.0 — 多人版

給急診 UGY / PGY 的 TRM（團隊資源管理）教學用。
學員各拿一支手機，投影幕放全景，教師另有一台控制台。
全程資訊不對稱：**你查到的事、你摸到的脈搏，不講出來別人就不知道。**

> **引擎版本 `4.0.0`**。錄影檔會記下產生它的引擎版本，版本不同就不能忠實重播
> —— 詳見〈[重播](#重播)〉與〈[要拿來做研究的話](#要拿來做研究的話)〉。
>
> ### ⚠ v4.0 是破壞性改版
> 結局模型、亂數流、判讀流程、藥物清單全部改過。
> **v3.x 產生的錄影檔在本版不能重播，也絕對不可以與新資料合併分析。**
> 主要變動整理在〈[v4.0 改了什麼](#v40-改了什麼)〉。

## v4.0 改了什麼

上一版有幾個會直接影響研究結論的問題，這一版全部處理掉了。

### 結局模型（最重要）

| v3.4 的狀況 | v4.0 |
|---|---|
| 校準實測整體 ROSC **88%**，修掉一個碰撞 bug 之後 **24 格全部 100%** | 難度變成 CCF 與「多久才處理病因」的連續函數，見〈[反應曲面](#反應曲面)〉 |
| 「生疏」腳本的 ROSC 率**高於**「稱職」腳本 | 三檔行為水準單調排序 |
| asystole／PEA 是最好打的兩格，方向與真實 IHCA 相反 | 加入心律乘數（asystole ×1.9、PEA ×1.35、VF/pVT ×1.0） |
| 起效判定用「當下 CCF」當門檻，先亂壓再補救可以把流逝的時間全數認列 | 改成累積有效灌流時間 `roscProgress += dt / (CCF懲罰 × 心律乘數)` |
| 沒有任何不可逆的路徑，只要找到病因就一定救得回來 | 加入累積 no-flow 債：180 秒後代價線性上升，420 秒完全回不來 |
| 開場 30 秒內電擊只有 5% 成功率（早期去顫被懲罰） | 移除 30 秒懸崖，並加上早期去顫加成 |

### 錯誤的處置開始有代價

v3.4 完全不做鑑別診斷、把所有侵入處置與藥物依序做一遍，六種病因**全部**在 68–185 秒內 ROSC ——
比認真推理的隊伍還快。v4.0：

* **沒有指徵的針刺減壓**：40% 造成醫源性氣胸。病人會慢慢變差，重掃超音波才看得到
  —— 學員要自己發現是自己造成的，再自己處理掉。
* **沒有指徵的心包穿刺**：30% 傷到心肌，不可回復。
* **經驗性 Calcium（非高血鉀情境）**：起效時間 ×1.35，並額外扣灌流 2 分鐘。
  這不是設計者的偏好，是有實證的：
  COCA RCT（OHCA，n=391，因安全性提前中止）sustained ROSC 19% vs 27%（RR 0.72）；
  單中心 IHCA 世代（n=599）校正後 ROSC OR 0.46、出院存活 OR 0.36、良好神經預後 OR 0.20。
* **活動性消化道出血病人給血栓溶解劑**：×2.2 並持續扣灌流，幾乎必死。
* 報表新增一整組「鑑別診斷與醫源性傷害」，含「沒有任何線索就做的侵入處置」次數。

### 臨床內容

* **低血容**的正解改成**輸血 pRBC**（原本只認晶體液，但教案是肝硬化併食道靜脈瘤、Hb 6.2）。
  快速輸液算部分處置（起效時間 ×1.67）。
* **高血鉀**的正解是 **Calcium**；Sodium bicarbonate 降為部分處置（×1.8）。
* 「低血氧（痰液阻塞）」改成 **上呼吸道阻塞（異物）** —— 痰液阻塞真正的處置是抽吸，
  插管不必然解除。新病因在**喉頭鏡放進去的當下就會全場公告**「口咽有大量食物殘渣」，
  不需要有人手動宣告。
* 急救車的「抽藥」拆成 **藥物** 與 **點滴及輸血**（pRBC / Normal saline）。

### 判讀與確認（教學上最大的兩個改動）

* **插管之後，系統不再告訴你對不對。** 畫面不會變紅、也不會跳「EtCO₂ 沒有波形」。
  床頭的人要按「確認管路位置」，接上 EtCO₂、擠球 8 秒，自己看有沒有連續方波，
  然後宣告「位置正確」或「拔管重來」。判讀錯誤會被記錄，但系統不會糾正你。
  （順帶解決了舊版「食道插管之後永遠不能改回甦醒球」的問題。）
* **PEA 不能用看的。** 心律判讀改成三步：
  ① 螢幕上是什麼電氣活動（VF / VT / **有組織的電氣活動** / 無電氣活動）
  → ② 有組織的話，**摸得到脈搏嗎**（要有人真的去摸並喊出來）
  → ③ 電還是不電。
  沒有人摸過就直接宣告 PEA，系統不擋，但報表會單獨列出來。

### 溝通

* **Order 改成佇列**，同時最多三則。舊版單一插槽會讓指令下得快的 Leader 複誦率被系統性低估
  —— 那是量測假象，不是團隊表現。
* **「回報完成」會被查證**：像「開始壓胸」「建立血管通路」「Epinephrine 1 mg」這種可以檢查的指令，
  系統會去看到底做了沒，報表分開列「回報完成」與「其中可查證為真」。
* **提出疑慮可以被回應**（CUS 的重點在被聽見）。報表新增「疑慮被回應的比例」與「回應延遲中位數」。
* **畫面下方的「收到」**：任何人回報或下令之後，其他人的病房畫面下方會出現一條「收到」，
  三秒內沒點就消失。不強迫，但看得到誰有回應。
* **急救車的人可以問床頭要什麼插管器材**，床頭的人手機會跳出三步選擇視窗，
  選完之後急救車那邊就多一顆「照 X 指定備妥」。

### 介面

* **對話、Order、系統訊息全部走右側同一條訊息流**，字級一律相同（不再依重要性放大）。
  訊息欄不再覆蓋病房畫面 —— 畫布自己讓出右邊那一欄，床右、電擊器、家屬永遠看得到。
  直立手機也看得到完整歷史，可以往下捲；右上角的箭頭可以把它收起來。
* **橫向手機與 iPad 改成雙欄**：左邊病房、右邊操作面板。
* 心律判讀大圖在**還沒貼上監測貼片時畫成灰色虛線**並寫明「沒有訊號」，
  跟真正的 asystole（實線、有細微雜訊）分得開。
* Leader 的標示從頭上 126 px 移到 66 px（貼著人物頭頂）。
* 修好「送出紀錄」按鈕（舊版點下去會丟例外，紀錄永遠送不出去）。
* 回報過的項目會從「回報 ▸」清單裡消失。

### 研究與資安

* **`/recordings` 加上教師金鑰驗證。** v3.4 的靜態伺服器完全沒有驗證，
  部署到公開網址之後任何人都可以列出並下載全部含學員資料的錄影檔。
* **入場代碼（`j=`）每一場可以換一組**，教師控制台一鍵更新；還可以「鎖定入場」。
  舊的 QR code 截圖立刻失效。
* **學員登入多了人事號與年資**。人事號不會顯示在任何畫面上，只用來跨場次比對同一個人。
* **匿名模式 `ANON=1`**：錄影檔只留 `P1…P6` 與人事號的 HMAC，不留姓名字。正式收資料請一定要開。
* **亂數流分離**：上針、插管、電擊、併發症各走一條獨立的種子流。
  這樣「兩組跑在完全相同的隨機條件下」這句話才是真的。
* 錄影檔新增 `roster`、`sessionIndex`、`familiarizationAge`。
* `batch.js` 的信賴區間改用 Wilson score（Wald 在比例接近 1 時會退化成 `[100,100]`）。
* 報表最前面自動產生「**這一場最該改的三件事**」，泳道圖移到數字表前面。
* 換手門檻 150→120 秒、未檢查間隔 140→120 秒、開始壓胸延遲 60→20 秒（對齊指引）。

## 檔案

| 檔案 | 用途 |
|---|---|
| `server.js` | 伺服器（零外部套件，只用 Node 內建模組） |
| `ihca-sim.js` | 模擬核心，伺服器與瀏覽器共用。所有可調參數在最上面的 `K = {…}` |
| `qr.js` | QR code 產生器（自己寫的，不需要連外） |
| `ihca-client.html` | 客戶端，同一個檔案切換五種模式 |
| `mailer.js` | 極簡 SMTP 寄信（零外部套件）。沒設環境變數就自動關閉 |
| `mkrec.js` | 產生一場「大致做對」的示範錄影，用來檢查報表與泳道圖（`npm run demo`） |
| `batch.js` | 難度校準：固定行為腳本、大量更換情境與種子（`npm run calibrate`） |
| `package.json` / `render.yaml` | 雲端部署用。**version 必須與 `ihca-sim.js` 的 `ENGINE` 一致** |
| `extras/` | `Dockerfile` 與 `fly.toml`，給 Fly.io 等平台用（Render 用不到） |
| `recordings/` | 錄影檔自動存在這裡（已列入 `.gitignore`，不會進 repo） |

事前只要裝一次 **Node.js**（<https://nodejs.org> 下載 LTS 版，一直按下一步）。

> **`Dockerfile` 一定要留在 `extras/`，不要放回根目錄。**
> Render 只要在根目錄看到 `Dockerfile` 就會自動把 Language 切成 Docker，
> Build Command / Start Command 兩格會整個消失，`render.yaml` 也形同虛設。

## 三種上線方式，挑一個

### A. 臨時公開網址（最快，不用註冊任何帳號）★ 建議先用這個

**適用你的情境**：桌機接網路線、學員用院內加密 WiFi，兩邊不同網路。

先裝一次 cloudflared（只要一次）：

```
Windows :  winget install --id Cloudflare.cloudflared
macOS   :  brew install cloudflared
```

上課時：

```
node server.js --tunnel
```

終端機會印出一個 `https://xxxx.trycloudflare.com` 開頭的公開網址。
學員的手機不管接哪個 WiFi、甚至用 4G，都連得到。

> 網址每次執行都不一樣 —— 但學員是**掃 QR code** 進來的，所以不影響。
> 關掉終端機，網址就失效，不會留著。

### B. 固定網址（部署到 Render，免費）

適合「每次上課都是同一個網址」、或你不想在上課時多開一個終端機。

#### 1. 先把檔案放到 GitHub

到 <https://github.com> 註冊 → 右上角 **+** → **New repository** →
取個名字（例如 `ihca`）→ **Create repository**。

進到新建好的頁面，點 **uploading an existing file**，把資料夾裡的檔案全部拖進去，
最下面按 **Commit changes**。

> 演練錄影檔含學員的操作紀錄與代號，`.gitignore` 已經把 `recordings/*.json` 排除。
> 如果 repo 設成 Public，請確認這一條有生效。

#### 2. 在 Render 建立服務

到 <https://render.com> 用 GitHub 帳號登入 → **New +** → **Web Service**
→ 選剛剛那個 repository → **Connect**。

接下來是**一頁很長的表單**，由上往下依序是：

| 欄位 | 要填什麼 |
|---|---|
| **Name** | 隨便取，例如 `ihca` |
| **Language** | **選 `Node`** ← 這一格以前叫 Runtime |
| **Branch** | `main`（預設值就對） |
| **Region** | 選 `Singapore` 或 `Oregon` 都可以 |
| **Root Directory** | **留空** |
| **Build Command** | 預設會自動填 `npm install`，**不用改** |
| **Start Command** | 預設會自動填 `npm start`，**不用改** |
| **Instance Type** | 往下捲，選 **Free**（`$0/month`） |

> **找不到 Build Command / Start Command 那兩格？**
> 那是因為 **Language 被設成 `Docker`** 了 —— 檢查根目錄是不是又出現 `Dockerfile`。
> 它應該在 `extras/` 底下。
>
> 如果服務**已經**被建成 Docker 模式，移掉根目錄的檔案後不一定會自己切回來。
> 到 **Settings** 看 Language 能不能改；改不了就刪掉服務重建一次（環境變數要重設）。

#### 3. 加兩個環境變數

同一頁往下找到 **Environment Variables**，加這兩組：

| Key（名稱） | Value（值） |
|---|---|
| `ROOM` | 你要的四位數房間代碼，例如 `2468` |
| `TKEY` | 你自己想一組英數字當教師金鑰 |
| `ANON` | 正式收資料填 `1`（錄影檔只留 P1…P6 與人事號雜湊） |
| `ANON_SALT` | 一組隨機英數字，**固定不要改**，跨場次才比對得到同一個人 |

> **`TKEY` 一定要設。** 沒設的話伺服器會用隨機值當教師金鑰，
> 服務每次重啟就換一組，你手上的教師網址會失效。

#### 4. 建立

最下面按 **Deploy Web Service**。等一兩分鐘會出現一個像
`https://ihca-xxxx.onrender.com` 的固定網址。

以後上課只要開：

* 投影幕 `https://你的網址/?m=host&k=你的教師金鑰`
* 教師 　 `https://你的網址/?m=teacher&k=你的教師金鑰`
* 學員 　 掃投影幕上的 QR code（房間代碼與**入場代碼**都會自動帶入）

> **入場代碼**（網址上的 `j=`）由伺服器每次啟動時隨機產生，
> 教師控制台可以隨時按「換一組入場代碼」。換過之後，之前掃過的 QR code
> 與學員手機裡的截圖都不能再進來。也可以按「鎖定入場」，
> 演練開始後就不再讓新的人加入。

> **免費方案會睡著**：15 分鐘沒人用會休眠，下次開要等 30–60 秒醒來。
> 上課前 5 分鐘先開一下投影幕那個網址就好。
>
> **錄影檔要當天帶走**：免費方案的硬碟是暫時的，重新部署或休眠後會清空。
> 課後請用教師控制台的「下載錄影檔」存到自己電腦。

### C. 同一個 WiFi（最單純）

```
node server.js
```

終端機會印出 `http://192.168.x.x:8080/?r=代碼`，手機連同一個 WiFi 就能開。

### 補充：Fly.io

設定檔在 `extras/`，從 repo 根目錄執行：

```
fly volumes create ihca_data --region nrt --size 1     # 只要做一次
fly deploy --config extras/fly.toml
```

`extras/fly.toml` 裡有掛載 `recordings/`，錄影檔可以活過重啟。
但**課後下載存到自己電腦仍然是主要做法**，掛載只是多一層保險。

## 上課流程

### 三個畫面

| 誰 | 開哪個網址 | 看得到什麼 |
|---|---|---|
| **投影機** | `…/?m=host&k=金鑰` | 大廳時是 QR code 與房間代碼；開始後是病房全景、監視器、指令橫幅、大字訊息流。沒有任何操作按鈕 |
| **教師** | `…/?m=teacher&k=金鑰` | 人數、情境設定、熟悉環境、開始、暫停、加速、結束、報表、下載錄影，以及同一份 QR |
| **學員** | 掃 QR（或輸入網址 + 四位數房間代碼） | 自己的角色、自己的動作面板、只有自己看得到的私訊 |

### 步驟

1. 投影幕開 host 網址 → 出現大 QR code 與房間代碼。
2. 教師控制台先選 **這一場有幾個人（3–6）**。
   沒用到的角色不會出現在病房裡，報表也不會列。
3. 學員掃 QR → **輸入一個字**（名字裡挑一個）→ 選顏色 → 進入。
   那個字就是他在投影幕上的代號。
4. **先按「先進熟悉環境（練習假人）」** —— 見下一節。
5. 熟悉完按「結束熟悉、回到教案設定」，**人數、名字、顏色都會保留，不用重掃 QR**。
6. 教師選 **點滴 / 起始心律 / 病因**，按「開始演練」。
7. 六個人（或 n 個人）從門口進場 —— 系統不會指派任何人任何事。
8. 要 pause-and-discuss 就按「⏸ 暫停」，所有人的畫面一起凍結。
9. 按「結束並看報表」。

### 熟悉環境（v3.4 新增）

**目的不只是讓學員別手忙腳亂。** 如果有人第一次用、有人已經玩過三輪，
「找按鈕的時間」會混進複誦延遲、ROSC 確認延遲這些指標裡，
而熟悉度剛好與「第幾次參加」相關 —— 這會直接污染跨場次的比較。

練習假人：
* 沒有正確答案，怎麼做都不會活過來
* 節律不會惡化、不會 ROSC、沒有時限、沒有家屬干擾
* 三條線索的文字直接寫明「這是練習用的」，不會被誤當成教案答案
* **不錄影**

教師端會看到一張「學員 × 七項核心互動」的檢核表，即時打勾：

> 走到一個站位 · 拿起器材 · 開始壓胸 · 做一項處置 · 講一句話 · 複誦一則 order · 喊出一條線索

全員全綠時會顯示總耗時，這個秒數會寫進之後那場正式錄影的
`familiarization` 欄位 —— 分析時可以直接當共變量用。

### 報表

## 手機怎麼操作

因為學員是**看投影幕、不是看手機**，操作設計成不用盯著螢幕也能做：

* **走路**：手指按住病房畫面的**任何一個位置**，往哪個方向拖就往哪裡走，放開就停。
  搖桿會長在你手指按下去的地方，所以不用找。
* **快速定位**：輕點某個站位或設備（不拖曳），就會自動走過去。
* **到站會震動**：走進床左、床右、床頭、床尾、門口或任何設備旁邊時，手機會震一下。
* **面板最上面一行**永遠寫著「你在：床左」「手上：留置針」。
* **動作分三層**：① 現在能做的處置 → ② 溝通 → ③ 準備與雜項。
* **① 層依臨床優先序排**，不是照程式碼順序：
  判讀宣告 → 手上有東西就用掉 → 壓胸相關 → 摸脈搏／NIBP → 診斷類。
  拿著藥站在床邊時，「推藥」就在最上面。
* **正在執行處置時，② 溝通層仍然開放。** 一邊上針一邊回報是常態，
  介面不該把做事的人變成啞巴（這也會讓溝通指標系統性偏低）。
* **會中斷壓胸的動作會標出來**，例如「摸脈搏 5s（會中斷壓胸）」。
  只警示、不攔阻 —— 不小心中斷壓胸本來就是要拿出來討論的事。
* **下 Order 是兩段式**：先選類別、再選句子，最後選對象（頭像色塊，也可以「不指定」）。
  同時最多三則未結案，每一則各自有自己的「複誦」與「回報完成」。
* **右側永遠有一條訊息流**：對話、Order、系統提示全部在裡面，字級一律相同。
  它不會蓋住病房 —— 病房畫面自己讓出那一欄。右上角的箭頭可以收起來。
* **橫向手機與 iPad**：自動切成左病房、右操作面板的雙欄版面。
* **有人回報時，畫面下方會跳出「收到」**，三秒內沒點就消失。
* **插管之後床頭會先出現「確認管路位置」**（淺綠色框）：按下去會接上 EtCO₂ 並自動擠球 8 秒，
  跳出跟心律判讀一樣的動態波形，由你判讀「位置正確」或「拔管重來」。
  確認完才會出現通氣節拍：進度條走完 6 秒閃紅提醒該給氣了。
* **按鈕按下去會震一下並閃一下**，不用等伺服器回話才知道有沒有按到。

## 重播

開 `…/?m=replay`，選伺服器上的錄影檔或從電腦上傳 `.json`。

錄影檔只有幾十 KB —— 它記的是**隨機種子加上每一個操作**，播放時把整場重新算一次。
所以可以：

* 任意拉時間軸（往前往後都可以）
* 1× / 2× / 4× / 8× 變速
* **切換視角**：看任何一個人當時收到的私訊
* 隨時叫出報表

> ### ⚠ 錄影檔綁定引擎版本
> 重播是「同樣的種子 + 同樣的操作序列，重算一次」。
> 只要模擬邏輯改過，同一份錄影檔就會算出**不一樣的一局**。
>
> 所以錄影檔會記下 `engine` 欄位，載入時如果版本不符會直接拒播並說明原因。
> **v3.3 以前產生的錄影檔在本版無法重播，也不應該與新資料合併分析。**

### 生理引擎（三件事決定病人活不活）

1. **灌流**：不壓胸時節律以 0.62/秒惡化，最好的壓胸只能回復 0.495/秒
   —— 整局是淨虧損的比賽。**病因處理完之後這筆帳照樣在跑**，
   找到答案不等於贏了，還要撐到起效。
2. **除顫**：可電擊節律有機率轉律（受焦耳數、近期 CCF、Epinephrine、Amiodarone、時間影響）。
   **轉律成功但病因沒解除 → 變成 PEA**，還是摸不到脈搏。
3. **病因**：六種可逆病因，處理正確後還要等一段時間起效，
   而這段時間會被壓胸品質拉長（見下）。

#### 起效怎麼算（v4.0 改寫）

處理完病因之後，引擎累積的是**有效灌流時間**，不是牆上的時間：

```
每一個 tick：  roscProgress += dt / ( CCF懲罰 × 心律乘數 )
ROSC 條件：    roscProgress ≥ 起效時間 × 沒給 epi 的懲罰 ÷ 處置品質
                             × 醫源性傷害倍率 × no-flow 倍率
               且 近期 CCF ≥ 40%　且 目前不是可電擊節律
               且 管路沒有插錯　且 沒有未處理的醫源性氣胸
               且 累積 no-flow < 420 秒
```

舊版是拿「當下的 CCF」去比一個門檻，所以 CCF 一改善，已經流逝的時間就全數認列
—— 先亂壓三分鐘再補救不會有實質代價。改成累積之後就不會。

**CCF 懲罰**（錨點採現行指引的兩個值）：

| 近期 CCF（最近 120 秒） | 倍率 |
|---|---|
| ≥ 80%（理想目標） | ×1.0 |
| 60–80%（達到基本門檻） | ×1.0 → ×1.5，線性 |
| 40–60%（低於基本門檻） | ×1.5 → ×3.0，斜率變陡 |
| < 40% | 完全不累積 —— 等於沒有在灌流 |

**心律乘數**：VF / pVT ×1.0、PEA ×1.35、asystole ×1.9。
方向依真實 IHCA 的預後：可電擊節律優於不可電擊節律
（US NIS 1998–2018 出院存活率，可電擊 29.8%→39.7%、不可電擊 18.9%→30.2%）。
v3.4 剛好相反，asystole 是最好打的一格。

**累積 no-flow 債**：第一次壓胸之後，每一秒沒有在壓都會記帳，而且不會歸零。

| 累積 no-flow | 效果 |
|---|---|
| < 180 秒 | 沒有額外代價 |
| 180 → 420 秒 | 起效時間 ×1 線性拉到 ×3 |
| ≥ 420 秒 | 不可能 ROSC —— 灌流債已經還不回來 |

> 指引內的心律檢查停頓只計 **0.5 倍**。生理上一樣沒有灌流，
> 但教學上不該懲罰照規矩做的停頓。這是刻意的模型選擇，論文的 Methods 要寫清楚。

報表會分開告訴團隊：因壓胸品質延長了幾秒、因為節律本身延長了幾秒、
因醫源性傷害延長了幾秒、因累積無灌流延長了幾秒。

#### 其他生理設定

* **疲勞不會讓人倒地**，而是讓整個節奏垮掉：速率從 110 降到 80 出頭、
  深度變淺、EtCO₂ 跟著掉。連續壓 240 秒到滿載，休息 120 秒回復。
  照指引每 2 分鐘換手時疲勞剛好在一半。**速率在投影幕上看得到**，全隊都能觀察到。
* **Epinephrine** 提高有壓胸時的灌流效率、提高轉律機率；
  沒有給的話病因起效時間 ×1.5。首劑時機依節律判斷：
  可電擊節律應在**初始電擊失敗之後**才給，不可電擊節律應在 5 分鐘內給。
* **Amiodarone** 只有在**第 3 次電擊之後、且當下仍是可電擊節律**時才算用對，
  也才有轉律加成。
* **ROSC 之後團隊不會自動知道** —— 螢幕變成規則心律（已插管的話 EtCO₂ 還會跳到 40），
  要有人去摸脈搏並喊出來，或由 Leader 在心律判讀的第二步宣告「摸得到脈搏」。
  沒發現而繼續壓胸 45 秒，病人會再度停止。
* **電擊轉律機率 `shockP()` 的每一個係數**（論文附錄要整表照抄）：

  | 因子 | 效果 |
  |---|---|
  | 基準 | 0.42 |
  | 焦耳數 120 / 150 / 200 | −0.04 / +0.02 / +0.08 |
  | 近期 CCF | (CCF − 0.70) × 0.5；資料不足時不套用 |
  | **早期去顫加成** | max(0, (150 − t) / 150) × 0.28 |
  | pVT 而非 VF | +0.08 |
  | 5 分鐘內給過 Epinephrine | +0.08 |
  | 3 分鐘內給過 Amiodarone（用對時機） | +0.15 |
  | 經過時間 | −min(0.22, t/60 × 0.022) |
  | 灌流債 | −(decay/105) × 0.15 |
  | 上下限 | 夾在 0.04–0.92 |

## 六種可逆病因與線索

**超音波線索只描述所見，不給結論。** 鑑別診斷是學員的工作，不是系統的。

| 病因 | 正解 | 部分處置 | 起效 | 常見起始心律 |
|---|---|---|---|---|
| 高血鉀症 | **Calcium gluconate** | Sodium bicarbonate（×1.8 慢） | 30 秒 | VF / PEA / asystole |
| 肺栓塞 | 血栓溶解劑 | — | 90 秒 | PEA |
| 低血容（消化道出血） | **輸血 pRBC** | Normal saline（×1.67 慢） | 45 秒 | PEA / asystole |
| 張力性氣胸 | 針刺減壓 | — | 15 秒 | PEA |
| **上呼吸道阻塞（異物）**（v4.0 改寫） | 解除阻塞並建立進階氣道 | — | 90 秒 | PEA / asystole |
| 心包填塞 | 心包穿刺引流 | — | 25 秒 | PEA |

> 「起效」是**有效灌流時間**，不是牆上的時間。壓胸品質差、節律是 asystole、
> 或做過有害的處置，都會把它拉長 —— 見下面的〈生理引擎〉。

<details>
<summary><b>展開看三條線索的完整內容（教師用，學員不要看）</b></summary>

**高血鉀症**
* 病歷：長期血液透析，前天因故沒有透析，上次 K 5.8。
* 家屬與護理師：今天整天喊沒力氣、手腳發麻，沒特別喘。
* 床邊超音波：心臟收縮微弱、心室不大；沒有心包積液、右心不擴大、IVC 不塌陷。

**肺栓塞**
* 病歷：兩週前髖關節置換術後長期臥床，沒有預防性抗凝。
* 家屬與護理師：下床上完廁所回來就一直喘，講一講就倒了。
* 床邊超音波：右心室明顯擴大，心室中膈呈 D-shape；沒有心包積液。

**低血容（消化道出血）**
* 病歷：肝硬化併食道靜脈瘤，今晨 Hb 6.2。
* 家屬與護理師：剛剛解了一大灘黑便，血壓量不到就叫人了。
* 床邊超音波：左心室空虛、收縮激烈，IVC 完全塌陷；沒有心包積液。

**張力性氣胸**
* 病歷：昨天剛放右側中心靜脈導管，之後沒有再照胸片。
* 家屬與護理師：突然說喘，血壓一下就掉，兩三分鐘就沒反應。
* 床邊超音波：右側完全沒有 lung sliding，看得到 lung point；心包沒有積液。

**上呼吸道阻塞（異物）**
* 病歷：中風後吞嚥困難，一直沒有做吞嚥評估，今天家屬自己餵了晚餐。
* 家屬與護理師：吃到一半突然講不出話、抓著脖子，臉色一下就發黑了。
* 床邊超音波：心臟收縮微弱，雙側肺滑動都在；沒有心包積液、右心不大、IVC 不塌陷。
* **喉頭鏡視野（插管時全場自動公告，不需要有人宣告）**：口咽有大量食物殘渣堵住。

**心包填塞**
* 病歷：昨天做完心導管，術後血壓一直偏低，沒有再追蹤心臟超音波。
* 家屬與護理師：這一兩個小時越來越喘、講話很費力，臉色發灰。
* 床邊超音波：心包大量積液，右心房在舒張期塌陷。

**設計上要知道的**：高血鉀與上呼吸道阻塞的超音波所見都是純排除性的，彼此無法區分
—— 這是臨床事實。掃到的人仍然要喊出來，「陰性所見也是資訊」本身就是
shared mental model 的教學點。相對地，肺栓塞、張力性氣胸與心包填塞的超音波
是決定性的，這三個情境會讓「去掃超音波」的角色價值非常明確。

## 要拿來做研究的話

這個工具的方法學優勢是**完全可重現**：`mulberry32` 種子亂數 + 固定 30Hz 步進 +
只記錄種子與操作序列。任兩組可以跑在位元層級完全相同的情境上，事後可以無限次
重新分析。實體模擬做不到這件事。

### 主要結局請用過程指標，不要用 ROSC

模擬器裡**每一場都有可逆病因**，真實世界不是。所以 ROSC 在這裡量到的其實是
「你多快找到答案」，外部效度接近零。建議：

* **主要結局：CCF（自第一次壓胸起算，`num2/den2`）** —— 符合 Utstein 慣例，有現成的品質門檻可比。
* 次要：開始壓胸的延遲、開始後最長中斷、被指名者複誦率、
  第一條線索被公開的時間（time-to-cause-identification）。
* ROSC 與總時長當**探索性**結局。

### 效度證據（審稿人一定會問的第一件事）

這個工具目前沒有任何與既有量表的對照。最小可行方案：
同一批演練另外請兩位不知情的教師用 **TEAM tool**（或 Ottawa GRS）獨立評分，然後報三個數字
—— ① 評分者間信度 ICC；② 自動指標與人評總分的相關（concurrent validity）；
③ 自動指標能不能區分年資（known-groups validity，例如 UGY vs PGY2）。

### 分析單位是團隊，不是個人

同一批人跨場次是重複測量；同一場次內的個人指標互相依賴。
用 mixed model / GEE，team 當 random effect，場次序號（錄影檔的 `sessionIndex`）當固定效果。
共變量至少放：熟悉環境的全員完成時間、年資（登入時收）、是否上過 ACLS、這一場的人數。
以團隊為單位、每組跑 3–4 場，要偵測 CCF 10 個百分點的差異（SD 約 10–12），大約需要 20–25 個團隊。

### 收資料之前必須先做的事

1. **凍結引擎版本。** 正式收資料開始後，`ihca-sim.js` 的 `ENGINE` 與
   `package.json` 的 `version` 都不再變動。改過任何影響模擬結果的邏輯，
   前後兩批資料就不能合併。
2. **難度校準。** `npm run calibrate:all` 會用三檔固定行為腳本跑遍所有病因 × 起始心律 ×
   大量種子。要主張兩個情境「難度相當」，請用等效性檢定（TOST）而不是一般 t 檢定
   —— p>0.05 只代表沒偵測到差異，不等於相等。
3. **熟悉環境會單獨存一份 `familiarization-*.json`**，記錄每個人七項核心互動各自的
   完成秒數、是否全員完成、以及全員完成的總時間。同一份摘要也會寫進之後那場正式錄影的
   `familiarization` 欄位，方便直接當共變量納入。
4. **錄影檔要當天帶走。** 雲端免費方案的硬碟是暫時的。
   （v4.0 起 `/recordings` 需要教師金鑰：`…/recordings?k=你的金鑰`。）
5. **CCF 有三個不同的定義，不要混用**：

   | 名稱 | 定義 | 用途 |
   |---|---|---|
   | 自第一次壓胸起算 | `num2 / den2` | **論文的主要 CCF**，符合 Utstein 慣例 |
   | 全場含到場時間 | `num / den` | 報表的次要對照欄位 |
   | 最近 120 秒 | `ccfRecent()` | **僅供引擎判定 ROSC，不是評分指標** |

6. **打開匿名模式。** 環境變數設 `ANON=1` 與一組固定的 `ANON_SALT`，
   錄影檔就只會存 `P1…P6` 與人事號的 HMAC，不留姓名字。
   鹽要固定住，跨場次才比對得到同一個人；鹽本身不要進 Git。

### 反應曲面

單一個 ROSC 率沒有意義。`node batch.js sweep` 會輸出 ROSC% 隨
「壓胸品質」與「多久才把正確處置做下去」變化的完整曲面 —— 這一張表才是論文該放的：

```

CCF       120    240    360    480    600    720     從未

90%      100%   100%   100%   100%   100%    83%    17%
80%      100%   100%   100%   100%   100%    79%    17%
70%      100%   100%   100%    96%    83%    38%    17%
60%       88%    83%    74%    68%    57%    11%    11%
50%       60%    56%    40%    38%    11%     0%     0%
40%       11%     0%     0%     0%     0%     0%     0%
```

（「從未」欄殘留的 ~17% 全部來自「上呼吸道阻塞」—— 那一格的正解本來就是插管，
而校準腳本不管幾分鐘都會去插管。其餘五種病因在該欄都是 0%。）

### 亂數流

v4.0 把上針、插管、電擊、併發症各拆成一條獨立的種子流
（`mulberry32(seed ^ 常數)`）。v3.4 全部共用一條，所以一支隊伍多做幾個動作，
之後所有隨機抽取都會平移 —— 「同一顆種子 = 同一個情境」成立，
「= 同樣的運氣」**不**成立。分流之後，Methods 裡「兩組跑在完全相同的隨機條件下」才是真的。

### 一定要寫進 Limitations 的四件事

* 「回報完成」是 **verbalized closure 的 proxy**。v4.0 對可查證的指令會去檢查有沒有真的做到
  （報表分開列），但仍有一部分指令無法自動查證。
* 電擊傷及旁人、ROSC 後持續壓胸導致再停止、無指徵處置的併發症機率，
  都是**刻意誇大的教學裝置**，不是生理模型。
* 手機介面的操作熟練度會混進所有延遲指標 —— 這正是熟悉環境階段要處理的，
  但只能部分校正。
* 模擬器裡每一場都有單一可逆病因，真實 IHCA 大多沒有。

> 錄影檔含學員的操作紀錄與代號。`.gitignore` 已排除 `recordings/*.json`，
> 但如果要做正式研究，請先送 IRB，並用不可逆的匿名代碼取代姓名字。

### 課後自動寄到院內信箱

v4.0 起，`render.yaml` 與 `extras/fly.toml` 的收件信箱是 **`A408J6@chimei.org.tw`**（院內）。

> **為什麼要用院內信箱？** 寄出去的是含學員代號的研究資料。
> 大多數 IRB 會要求研究資料不得經由商業郵件服務傳到個人帳號 ——
> 把它寄到院內信箱，資料就一直待在機構的邊界內，事後也說得清楚。
> 寄件帳號（`MAIL_USER` / `MAIL_HOST`）請一併改成院內 SMTP，並確認院內有開放。
> 如果院內 SMTP 只支援 STARTTLS（587）而不是 SSL（465），
> 目前的 `mailer.js` 連不上 —— 這種情況就把寄信關掉，改用教師控制台手動下載。

雲端免費方案的硬碟是暫時的，靠手動下載很容易忘記。設四個環境變數，
**每次存檔後伺服器會自動把檔案寄出**，正式演練的信件內文還會直接附上報表全文
—— 就算附件之後不見了，結論還留在信箱裡。

| 變數 | 填什麼 |
|---|---|
| `MAIL_TO` | 收件信箱 |
| `MAIL_USER` | 寄件帳號，例如 `you@gmail.com` |
| `MAIL_PASS` | **應用程式密碼**，不是你的登入密碼 |
| `MAIL_HOST` | 院內 SMTP 主機；可省略，預設 `smtp.gmail.com`（port 465） |
| `MAIL_PORT` | 可省略，預設 465（本工具目前只支援 SSL/465） |

四個變數任一沒設就整個功能關閉，不影響其他運作。

> ### ⚠ 應用程式密碼絕對不要寫進 repo
> `render.yaml` 的 `MAIL_PASS` 用 `sync: false`，Render 會在後台問你，值只存在 Render 那邊。
> Fly.io 則用 `fly secrets set MAIL_PASS=你的16碼`，不要寫進 `fly.toml`。
> 如果不小心提交過，請立刻到 Google 帳戶把那組應用程式密碼撤銷再產生新的
> —— Git 的歷史紀錄刪不掉。

教師控制台在結束後會多一顆「📧 補寄一份」，網路斷過或想再寄給共同主持人時可以用。

> 寄出的是含學員代號的研究資料。請用你自己的機構信箱，並確認符合 IRB 的資料保管規定。
