# IHCA 團隊復甦模擬器 v3.4 — 多人版

給急診 UGY / PGY 的 TRM（團隊資源管理）教學用。
學員各拿一支手機，投影幕放全景，教師另有一台控制台。
全程資訊不對稱：**你查到的事、你摸到的脈搏，不講出來別人就不知道。**

> **引擎版本 `3.4.0`**。錄影檔會記下產生它的引擎版本，版本不同就不能忠實重播
> —— 詳見〈[重播](#重播)〉與〈[要拿來做研究的話](#要拿來做研究的話)〉。

## 檔案

| 檔案 | 用途 |
|---|---|
| `server.js` | 伺服器（零外部套件，只用 Node 內建模組） |
| `ihca-sim.js` | 模擬核心，伺服器與瀏覽器共用。所有可調參數在最上面的 `K = {…}` |
| `qr.js` | QR code 產生器（自己寫的，不需要連外） |
| `ihca-client.html` | 客戶端，同一個檔案切換五種模式 |
| `mailer.js` | 極簡 SMTP 寄信（零外部套件）。沒設環境變數就自動關閉 |
| `mkrec.js` | 產生一場「大致做對」的示範錄影，用來檢查報表與泳道圖（`npm run demo`） |
| `batch.js` | 難度校準：固定行為腳本、大量更換情境與種子（`npm run calibrate`） |
| `package.json` / `render.yaml` | 雲端部署用。**version 必須與 `ihca-sim.js` 的 `ENGINE` 一致** |
| `extras/` | `Dockerfile` 與 `fly.toml`，給 Fly.io 等平台用（Render 用不到） |
| `recordings/` | 錄影檔自動存在這裡（已列入 `.gitignore`，不會進 repo） |

事前只要裝一次 **Node.js**（<https://nodejs.org> 下載 LTS 版，一直按下一步）。

> **`Dockerfile` 一定要留在 `extras/`，不要放回根目錄。**
> Render 只要在根目錄看到 `Dockerfile` 就會自動把 Language 切成 Docker，
> Build Command / Start Command 兩格會整個消失，`render.yaml` 也形同虛設。

## 三種上線方式，挑一個

### A. 臨時公開網址（最快，不用註冊任何帳號）★ 建議先用這個

**適用你的情境**：桌機接網路線、學員用院內加密 WiFi，兩邊不同網路。

先裝一次 cloudflared（只要一次）：

```
Windows :  winget install --id Cloudflare.cloudflared
macOS   :  brew install cloudflared
```

上課時：

```
node server.js --tunnel
```

終端機會印出一個 `https://xxxx.trycloudflare.com` 開頭的公開網址。
學員的手機不管接哪個 WiFi、甚至用 4G，都連得到。

> 網址每次執行都不一樣 —— 但學員是**掃 QR code** 進來的，所以不影響。
> 關掉終端機，網址就失效，不會留著。

### B. 固定網址（部署到 Render，免費）

適合「每次上課都是同一個網址」、或你不想在上課時多開一個終端機。

#### 1. 先把檔案放到 GitHub

到 <https://github.com> 註冊 → 右上角 **+** → **New repository** →
取個名字（例如 `ihca`）→ **Create repository**。

進到新建好的頁面，點 **uploading an existing file**，把資料夾裡的檔案全部拖進去，
最下面按 **Commit changes**。

> 演練錄影檔含學員的操作紀錄與代號，`.gitignore` 已經把 `recordings/*.json` 排除。
> 如果 repo 設成 Public，請確認這一條有生效。

#### 2. 在 Render 建立服務

到 <https://render.com> 用 GitHub 帳號登入 → **New +** → **Web Service**
→ 選剛剛那個 repository → **Connect**。

接下來是**一頁很長的表單**，由上往下依序是：

| 欄位 | 要填什麼 |
|---|---|
| **Name** | 隨便取，例如 `ihca` |
| **Language** | **選 `Node`** ← 這一格以前叫 Runtime |
| **Branch** | `main`（預設值就對） |
| **Region** | 選 `Singapore` 或 `Oregon` 都可以 |
| **Root Directory** | **留空** |
| **Build Command** | 預設會自動填 `npm install`，**不用改** |
| **Start Command** | 預設會自動填 `npm start`，**不用改** |
| **Instance Type** | 往下捲，選 **Free**（`$0/month`） |

> **找不到 Build Command / Start Command 那兩格？**
> 那是因為 **Language 被設成 `Docker`** 了 —— 檢查根目錄是不是又出現 `Dockerfile`。
> 它應該在 `extras/` 底下。
>
> 如果服務**已經**被建成 Docker 模式，移掉根目錄的檔案後不一定會自己切回來。
> 到 **Settings** 看 Language 能不能改；改不了就刪掉服務重建一次（環境變數要重設）。

#### 3. 加兩個環境變數

同一頁往下找到 **Environment Variables**，加這兩組：

| Key（名稱） | Value（值） |
|---|---|
| `ROOM` | 你要的四位數房間代碼，例如 `2468` |
| `TKEY` | 你自己想一組英數字當教師金鑰，例如 `emed2026` |

> **`TKEY` 一定要設。** 沒設的話伺服器會用隨機值當教師金鑰，
> 服務每次重啟就換一組，你手上的教師網址會失效。

#### 4. 建立

最下面按 **Deploy Web Service**。等一兩分鐘會出現一個像
`https://ihca-xxxx.onrender.com` 的固定網址。

以後上課只要開：

* 投影幕 `https://你的網址/?m=host&k=emed2026`
* 教師 　 `https://你的網址/?m=teacher&k=emed2026`
* 學員 　 掃投影幕上的 QR code（代碼會自動帶入）

> **免費方案會睡著**：15 分鐘沒人用會休眠，下次開要等 30–60 秒醒來。
> 上課前 5 分鐘先開一下投影幕那個網址就好。
>
> **錄影檔要當天帶走**：免費方案的硬碟是暫時的，重新部署或休眠後會清空。
> 課後請用教師控制台的「下載錄影檔」存到自己電腦。

### C. 同一個 WiFi（最單純）

```
node server.js
```

終端機會印出 `http://192.168.x.x:8080/?r=代碼`，手機連同一個 WiFi 就能開。

### 補充：Fly.io

設定檔在 `extras/`，從 repo 根目錄執行：

```
fly volumes create ihca_data --region nrt --size 1     # 只要做一次
fly deploy --config extras/fly.toml
```

`extras/fly.toml` 裡有掛載 `recordings/`，錄影檔可以活過重啟。
但**課後下載存到自己電腦仍然是主要做法**，掛載只是多一層保險。

## 上課流程

### 三個畫面

| 誰 | 開哪個網址 | 看得到什麼 |
|---|---|---|
| **投影機** | `…/?m=host&k=金鑰` | 大廳時是 QR code 與房間代碼；開始後是病房全景、監視器、指令橫幅、大字訊息流。沒有任何操作按鈕 |
| **教師** | `…/?m=teacher&k=金鑰` | 人數、情境設定、熟悉環境、開始、暫停、加速、結束、報表、下載錄影，以及同一份 QR |
| **學員** | 掃 QR（或輸入網址 + 四位數房間代碼） | 自己的角色、自己的動作面板、只有自己看得到的私訊 |

### 步驟

1. 投影幕開 host 網址 → 出現大 QR code 與房間代碼。
2. 教師控制台先選 **這一場有幾個人（3–6）**。
   沒用到的角色不會出現在病房裡，報表也不會列。
3. 學員掃 QR → **輸入一個字**（名字裡挑一個）→ 選顏色 → 進入。
   那個字就是他在投影幕上的代號。
4. **先按「先進熟悉環境（練習假人）」** —— 見下一節。
5. 熟悉完按「結束熟悉、回到教案設定」，**人數、名字、顏色都會保留，不用重掃 QR**。
6. 教師選 **點滴 / 起始心律 / 病因**，按「開始演練」。
7. 六個人（或 n 個人）從門口進場 —— 系統不會指派任何人任何事。
8. 要 pause-and-discuss 就按「⏸ 暫停」，所有人的畫面一起凍結。
9. 按「結束並看報表」。

### 熟悉環境（v3.4 新增）

**目的不只是讓學員別手忙腳亂。** 如果有人第一次用、有人已經玩過三輪，
「找按鈕的時間」會混進複誦延遲、ROSC 確認延遲這些指標裡，
而熟悉度剛好與「第幾次參加」相關 —— 這會直接污染跨場次的比較。

練習假人：
* 沒有正確答案，怎麼做都不會活過來
* 節律不會惡化、不會 ROSC、沒有時限、沒有家屬干擾
* 三條線索的文字直接寫明「這是練習用的」，不會被誤當成教案答案
* **不錄影**

教師端會看到一張「學員 × 七項核心互動」的檢核表，即時打勾：

> 走到一個站位 · 拿起器材 · 開始壓胸 · 做一項處置 · 講一句話 · 複誦一則 order · 喊出一條線索

全員全綠時會顯示總耗時，這個秒數會寫進之後那場正式錄影的
`familiarization` 欄位 —— 分析時可以直接當共變量用。

### 報表

* 八個分組：**結果 / 閉環溝通與領導 / 心律判讀 / 壓胸品質 / 氣道與通氣 / 血管通路與用藥 / 電擊與安全 / 現場管理**
* **泳道圖**：縱軸時間、橫軸每個人。壓胸是長橘條、找病因是紫、給藥是綠、倒地是紅；
  講話與下令是小菱形 —— 所以 Leader 那一欄會清楚看到他整場在說話而不是動手，
  誰整場沒事做也一目了然
* 用藥與電擊逐筆紀錄、關鍵事件時間軸、全場對話逐字稿
* 可以「複製報表文字」或「下載 .txt」帶走
* 最後一顆 **「▶ 重播這一場」** 會開新分頁直接載入剛剛那場的錄影檔，
  不用再去挑檔案。原本那一頁保持連線，投影幕不會斷。

**v3.4 報表新增或改定義的欄位：**

| 欄位 | 說明 |
|---|---|
| CCF（自第一次壓胸起算） | 主要指標，符合 Utstein 慣例。<60% 紅、60–80% 黃、≥80% 綠 |
| CCF（全場含到場時間） | 次要對照欄位 |
| 開始壓胸前的延遲 | 從前一版的 CCF 分母裡拆出來，反映團隊啟動速度 |
| 開始後最長中斷 | 與上一項拆開，不再混為一談 |
| 因壓胸品質而延長的起效時間 | 分級懲罰的具體秒數，比布林值好教 |
| 被指名者複誦 / 旁人代為回應 | 閉環溝通改為三段式，兩者分開計 |
| 執行後回報完成 | 閉環的第三段（TeamSTEPPS 的 closing the loop） |
| 複誦延遲 / 下令→完成（中位） | 改用中位數，抗離群值 |
| 提出疑慮 | CUS 三階的次數與最高強度 |
| 平均宣告時點 | Leader 的判讀速度，獨立於停頓長度 |
| Epinephrine 首劑時機 | 依當下節律判斷是否恰當（見下） |
| 插管後無通氣時間 / 通氣頻率 | 插管後不再自動給氣 |
| 疲勞下仍未換手的壓胸 | 取代舊的「壓到力竭倒下」 |
| 為了其他處置停手 | 壓胸者去做別的事而中斷的次數 |

## 手機怎麼操作

因為學員是**看投影幕、不是看手機**，操作設計成不用盯著螢幕也能做：

* **走路**：手指按住病房畫面的**任何一個位置**，往哪個方向拖就往哪裡走，放開就停。
  搖桿會長在你手指按下去的地方，所以不用找。
* **快速定位**：輕點某個站位或設備（不拖曳），就會自動走過去。
* **到站會震動**：走進床左、床右、床頭、床尾、門口或任何設備旁邊時，手機會震一下。
* **面板最上面一行**永遠寫著「你在：床左」「手上：留置針」。
* **動作分三層**：① 現在能做的處置 → ② 溝通 → ③ 準備與雜項。
* **① 層依臨床優先序排**，不是照程式碼順序：
  判讀宣告 → 手上有東西就用掉 → 壓胸相關 → 摸脈搏／NIBP → 診斷類。
  拿著藥站在床邊時，「推藥」就在最上面。
* **正在執行處置時，② 溝通層仍然開放。** 一邊上針一邊回報是常態，
  介面不該把做事的人變成啞巴（這也會讓溝通指標系統性偏低）。
* **會中斷壓胸的動作會標出來**，例如「摸脈搏 5s（會中斷壓胸）」。
  只警示、不攔阻 —— 不小心中斷壓胸本來就是要拿出來討論的事。
* **下 Order 是兩段式**：先選句子，再選對象（頭像色塊，也可以「不指定」）。
* **插管之後床頭會出現通氣節拍**：進度條走完 6 秒閃紅提醒該給氣了。
* **按鈕按下去會震一下並閃一下**，不用等伺服器回話才知道有沒有按到。

## 重播

開 `…/?m=replay`，選伺服器上的錄影檔或從電腦上傳 `.json`。

錄影檔只有幾十 KB —— 它記的是**隨機種子加上每一個操作**，播放時把整場重新算一次。
所以可以：

* 任意拉時間軸（往前往後都可以）
* 1× / 2× / 4× / 8× 變速
* **切換視角**：看任何一個人當時收到的私訊
* 隨時叫出報表

> ### ⚠ 錄影檔綁定引擎版本
> 重播是「同樣的種子 + 同樣的操作序列，重算一次」。
> 只要模擬邏輯改過，同一份錄影檔就會算出**不一樣的一局**。
>
> 所以錄影檔會記下 `engine` 欄位，載入時如果版本不符會直接拒播並說明原因。
> **v3.3 以前產生的錄影檔在本版無法重播，也不應該與新資料合併分析。**

## 教案設計重點

| 機制 | 教什麼 |
|---|---|
| 系統不指派角色，Leader 要自己宣告、可以交接 | Role clarity / Leadership |
| Order 可以指名對象；被指名者複誦、做完再回報完成（三段） | Closed-loop communication |
| 任何人隨時可以「提出疑慮」，三個強度由輕到重 | Graded assertiveness / 心理安全 |
| 三條線索（病歷／家屬／超音波）只有查到的人知道，要按「📢 大聲喊出」 | Shared mental model |
| 超音波線索只給**所見**，不給結論 —— 鑑別診斷要自己做 | 臨床推理 |
| 只有站在電腦車前才看得到急救經過幾分幾秒 | Situational awareness |
| 電擊器與超音波的線不夠長，一定要有人去推機器 | Resource management |
| 留置針只有 3 根、一次只能拿一樣東西、壓胸會累 | Resource management |
| **摸脈搏的結果只有摸的人知道**，要喊出來團隊才會停手 | Closed-loop / ROSC 辨識 |
| NIBP 任何人在床邊都能量，結果全隊都看得到 | 客觀證據 vs 個人感受 |
| 插管之前沒有 EtCO₂；插管之後沒人擠就是真的沒有通氣 | 進階氣道的價值與代價 |
| 心律檢查停頓上限 10 秒、最短 4 秒，Leader 必須宣告可／不可電擊 | 心律判讀與決策 |
| 沒喊 CLEAR 就放電會電到人；有喊則幾乎所有人來得及放手 | 病人與團隊安全 |
| 家屬會靠近、拉住人、讓所有工作變慢 35% | 現場管理與家屬溝通 |
| CCF 全程隱藏，結束才公布 | 不能靠儀表板打，要靠團隊自己管 |

### 生理引擎（三件事決定病人活不活）

1. **灌流**：不壓胸時節律以 0.62/秒惡化，最好的壓胸只能回復 0.495/秒
   —— 整局是淨虧損的比賽。**病因處理完之後這筆帳照樣在跑**，
   找到答案不等於贏了，還要撐到起效。
2. **除顫**：可電擊節律有機率轉律（受焦耳數、近期 CCF、Epinephrine、Amiodarone、時間影響）。
   **轉律成功但病因沒解除 → 變成 PEA**，還是摸不到脈搏。
3. **病因**：六種可逆病因，處理正確後還要等一段時間起效，
   而這段時間會被壓胸品質拉長（見下）。

#### 壓胸分率（CCF）怎麼影響結局

引擎看的是**最近 120 秒**的壓胸分率，不是全場平均 —— 冠狀動脈灌流壓取決於
最近這一兩分鐘，不是整局的成績單。錨點採現行指引的兩個值：

| 近期 CCF | 病因起效時間 |
|---|---|
| ≥ 80%（理想目標） | ×1.0，沒有懲罰 |
| 60–80%（達到基本門檻） | ×1.0 → ×1.5，線性 |
| 40–60%（低於基本門檻） | ×1.5 → ×3.0，斜率變陡 |
| < 40% | 不可能 ROSC —— 等於沒有在灌流 |

沒有懸崖，也不是全有全無。報表會直接告訴團隊「因壓胸品質而延長了幾秒」。

#### 其他生理設定

* **疲勞不會讓人倒地**，而是讓整個節奏垮掉：速率從 110 降到 80 出頭、
  深度變淺、EtCO₂ 跟著掉。連續壓 240 秒到滿載，休息 120 秒回復。
  照指引每 2 分鐘換手時疲勞剛好在一半。**速率在投影幕上看得到**，全隊都能觀察到。
* **Epinephrine** 提高有壓胸時的灌流效率、提高轉律機率；
  沒有給的話病因起效時間 ×1.5。首劑時機依節律判斷：
  可電擊節律應在**初始電擊失敗之後**才給，不可電擊節律應在 5 分鐘內給。
* **Amiodarone** 只有在**第 3 次電擊之後、且當下仍是可電擊節律**時才算用對，
  也才有轉律加成。
* **ROSC 條件**：病因已解除 **且** 管路正確 **且** 起效時間到（含 CCF 懲罰）
  **且** 近期 CCF ≥ 40% **且** 灌流債未過高 **且** 目前不是可電擊節律。
  達成後病人生理上恢復循環，但**團隊不會自動知道** —— 螢幕變成規則心律
  （已插管的話 EtCO₂ 還會跳到 40），要有人去摸脈搏並喊出來。
  沒發現而繼續壓胸 45 秒，病人會再度停止。

## 要拿來做研究的話

這個工具的方法學優勢是**完全可重現**：`mulberry32` 種子亂數 + 固定 30Hz 步進 +
只記錄種子與操作序列。任兩組可以跑在位元層級完全相同的情境上，事後可以無限次
重新分析。實體模擬做不到這件事。

要用它收資料，有五件事必須先做：

1. **凍結引擎版本。** 正式收資料開始後，`ihca-sim.js` 的 `ENGINE` 與
   `package.json` 的 `version` 都不再變動。改過任何影響模擬結果的邏輯，
   前後兩批資料就不能合併。
2. **難度校準。** `npm run calibrate` 會用固定的行為腳本跑遍所有病因 × 起始心律 ×
   大量種子，輸出 ROSC 率、CCF 分布、首次電擊轉律率。要主張兩個情境「難度相當」，
   請用等效性檢定（TOST）而不是一般 t 檢定 —— p>0.05 只代表沒偵測到差異，不等於相等。
3. **熟悉環境會單獨存一份 `familiarization-*.json`**，記錄每個人七項核心互動各自的
   完成秒數、是否全員完成、以及全員完成的總時間。同一份摘要也會寫進之後那場正式錄影的
   `familiarization` 欄位，方便直接當共變量納入。
4. **錄影檔要當天帶走。** 雲端免費方案的硬碟是暫時的。
5. **CCF 有三個不同的定義，不要混用**：

   | 名稱 | 定義 | 用途 |
   |---|---|---|
   | 自第一次壓胸起算 | `num2 / den2` | **論文的主要 CCF**，符合 Utstein 慣例 |
   | 全場含到場時間 | `num / den` | 報表的次要對照欄位 |
   | 最近 120 秒 | `ccfRecent()` | **僅供引擎判定 ROSC，不是評分指標** |

> 錄影檔含學員的操作紀錄與代號。`.gitignore` 已排除 `recordings/*.json`，
> 但如果要做正式研究，請先送 IRB，並用不可逆的匿名代碼取代姓名字。

### 課後自動寄到自己的信箱

（`render.yaml` 與 `extras/fly.toml` 裡的收件信箱已經填成 `ooleo76@gmail.com`，
要改的話直接改那兩個檔，或在雲端後台覆寫。）

雲端免費方案的硬碟是暫時的，靠手動下載很容易忘記。設四個環境變數，
**每次存檔後伺服器會自動把檔案寄出**，正式演練的信件內文還會直接附上報表全文
—— 就算附件之後不見了，結論還留在信箱裡。

| 變數 | 填什麼 |
|---|---|
| `MAIL_TO` | 收件信箱 |
| `MAIL_USER` | 寄件帳號，例如 `you@gmail.com` |
| `MAIL_PASS` | **應用程式密碼**，不是你的登入密碼 |
| `MAIL_HOST` | 可省略，預設 `smtp.gmail.com`（port 465） |

Gmail 要先開兩步驟驗證，再到 Google 帳戶的「應用程式密碼」產生一組 16 碼填進 `MAIL_PASS`。
四個變數任一沒設就整個功能關閉，不影響其他運作。

> ### ⚠ 應用程式密碼絕對不要寫進 repo
> `render.yaml` 的 `MAIL_PASS` 用 `sync: false`，Render 會在後台問你，值只存在 Render 那邊。
> Fly.io 則用 `fly secrets set MAIL_PASS=你的16碼`，不要寫進 `fly.toml`。
> 如果不小心提交過，請立刻到 Google 帳戶把那組應用程式密碼撤銷再產生新的
> —— Git 的歷史紀錄刪不掉。

教師控制台在結束後會多一顆「📧 補寄一份」，網路斷過或想再寄給共同主持人時可以用。

> 寄出的是含學員代號的研究資料。請用你自己的機構信箱，並確認符合 IRB 的資料保管規定。
